# Техническое задание: Claude Secure Network — v1.1

**Дата:** 19 ноября 2026 года; дополнено 20 ноября 2026 года  
**Статус:** ТЗ для реализации; не является доказательством внедрения  
**Целевая платформа:** Lenovo Legion Y70 с прошивкой Motorola  
**Ограничения:** без root; с возможностью использования Shizuku и Termux

---

## 1. Цель проекта

Создать изолированную сетевую среду для приложения Claude на Android, обеспечивающую:

- Подключение исключительно через заранее выбранный VPN-сервер.
- Запрет прямых соединений с интернетом при отсутствии VPN.
- Отсутствие автоматической смены страны и выходного сервера.
- Измеряемую проверку региональных параметров среды (включая часовой пояс), не изменяя их без отдельного разрешения.
- Предотвращение утечек IPv4, IPv6 и DNS.
- Автоматическое восстановление соединения после сбоев.
- Независимую работу остальных приложений телефона.

**Основной принцип: Fail Closed.** При любой ошибке защищённого подключения интернет для Claude должен блокироваться, а не переключаться на обычное соединение.

Решение обеспечивает сетевую изоляцию, но не гарантирует защиту от блокировок Anthropic или соблюдение региональных правил сервиса.

## 2. Архитектура

Использовать отдельный рабочий профиль Android, **если конкретная прошивка позволяет независимо применять требуемые VPN-политики к этому профилю**.

**Личный профиль:**
- Обычные приложения пользователя.
- Интернет через мобильную сеть или Wi-Fi.
- Отсутствие обязательного подключения к VPN Claude.

**Защищённый рабочий профиль:**
- Приложение Claude.
- Отдельный браузер для веб-версии и авторизации.
- VPN-клиент с поддержкой выбранного протокола (WireGuard или совместимый VLESS/XHTTP).
- Системная политика Always-on VPN.
- Режим Block connections without VPN (Lockdown).

Весь доступный для маршрутизации приложений рабочего профиля сетевой трафик должен проходить через защищённый туннель. Исключения, позволяющие приложениям обходить VPN, запрещены. Нельзя считать рабочий профиль защищённым только на основании факта установки VPN-клиента.

Базовый кандидат для создания рабочего профиля — Shelter. До внедрения проверить совместимость прошивки и возможность управления требуемыми политиками. Наличие Shelter само по себе **не гарантирует** работоспособности профильного Lockdown.

## 3. VPN-соединение

### 3.1. Сервер

Требования:
- Одна выбранная страна.
- Один закреплённый сервер.
- Предпочтительно выделенный постоянный публичный IP.
- Отсутствие автоматического выбора альтернативной страны.
- Отсутствие автоматического перехода на другой сервер.
- Поддержка полнодуплексного маршрута для необходимого трафика.

Расположение сервера и его IP фиксируются в локальной конфигурации. При смене IP требуется явное обновление конфигурации и повторная проверка. Конкретная страна пока не выбрана.

### 3.2. Клиент

Первоначальный вариант — официальный WireGuard для Android. **Фактически доступная подписка DUORAY использует VLESS + XHTTP, не WireGuard; отдельный экземпляр DUORAY уже запущен в рабочем профиле.** Решение о клиенте принимать после проверки его VPN-сервиса, настроек маршрутизации и поддержки профильного Lockdown. Данные подписки, токены и адреса серверов в Git не добавлять.

Обязательные настройки:
- Full Tunnel.
- Маршрутизация IPv4 через VPN.
- Маршрутизация IPv6 через VPN либо гарантированная блокировка IPv6 при отсутствии поддержки.
- DNS через защищённый маршрут.
- Запрет обхода VPN приложениями рабочего профиля.
- Always-on VPN.
- Lockdown при отсутствии подключения.

Для WireGuard проверить использование маршрутов `0.0.0.0/0` и `::/0` с корректной серверной поддержкой. Один лишь список AllowedIPs не заменяет системный Lockdown.

### 3.3. Обработка сбоев

| Событие | Обязательная реакция |
|---|---|
| VPN отключился | Немедленная блокировка интернета рабочего профиля |
| Сервер не отвечает | Блокировка, без смены сервера |
| Смена Wi-Fi на LTE | Сохранение Lockdown во время переподключения |
| Потеря DNS | Ошибка соединения, без перехода на прямой DNS |
| Перезагрузка телефона | Блокировка доступа до восстановления VPN |
| Принудительная остановка клиента | Отсутствие прямого доступа к сети |
| Обновление VPN-приложения | Сохранение или безопасное повторное применение политики |
| Приостановка рабочего профиля | Отсутствие незащищённого сетевого трафика |

## 4. Защита от сетевых утечек

### 4.1. IPv4

Любой публичный IPv4-адрес, наблюдаемый внешним тестовым сервисом из защищённого профиля, должен соответствовать выбранному VPN-выходу.

### 4.2. IPv6

Недопустимо прямое соединение по IPv6 в обход VPN. Если сервер не предоставляет IPv6-маршрутизацию, трафик IPv6 защищённого профиля должен блокироваться.

### 4.3. DNS

Все DNS-запросы защищённого профиля должны направляться через установленный VPN-маршрут. Проверить системный Private DNS, DNS браузера и системный резолвер. Не допускать прямого разрешения имён через провайдера.

### 4.4. WebRTC

Для браузера выполнить тест утечки публичных IP через WebRTC. Локальные адреса сами по себе не свидетельствуют об обходе VPN. Критерий отказа — обнаружение прямого публичного адреса или сетевого соединения вне туннеля.


### 4.5. Проверка региональных параметров среды

Проводить **проверку**, а не автоматическую подмену признаков местоположения. Цель — установить, какие параметры реально изолированы по рабочему профилю, выявить нежелательные глобальные изменения и задокументировать ограничения без обещаний предотвратить блокировку аккаунта.

- **Часовой пояс:** считать системный `persist.sys.timezone` и состояние автоматического определения часового пояса без изменения значений. У штатного Android нет гарантированной независимой настройки часового пояса для обычного рабочего профиля Shelter. Изменение системной зоны затрагивает личный профиль, отображение времени и планирование событий; **запрещено автоматически менять часовой пояс**. При выборе эстонского сервера соответствует IANA-идентификатору `Europe/Tallinn` (только справочно, не требование смены). Любое глобальное изменение — отдельное явное решение владельца и сценарий отката.
- **Язык и регион приложения:** проверить доступность системной настройки языка конкретного приложения. Изменение языка не является доказанной защитой от антифрода. Не менять язык всей системы и других приложений.
- **DNS, IPv4, IPv6, WebRTC:** подтвердить реальную сетевую маршрутизацию измерениями из рабочего профиля; состояние переключателей и страна на экране клиента недостаточны.
- **Непосредственный трафик и прокси-правила:** проверить все правила `direct`, `proxy`, `block`, `dns-out` в DUORAY; сетевые назначения должны соответствовать одобренной политике профиля. Исключения для локальной сети и системных служб согласовывать по необходимости; скрытый прямой egress недопустим.
- **Одна локация:** исключить авто-выбор и запасные сервера, зафиксировать наблюдаемый выходной IP как результат проверки, а не как обещание неизменности адреса.
- **Доступ к местоположению, SIM, устройство, аккаунт:** зафиксировать **только** принцип минимальных разрешений; не изменять GPS/SIM/идентификаторы, не собирать персональные или платёжные данные и не имитировать другую личность.

Сервисные ограничения Anthropic относятся к фактическому использованию сервиса в неподдерживаемом регионе и не исчезают после смены IP или часового пояса: [Supported Regions Policy](https://www.anthropic.com/legal/supported-regions). Описание общесистемного определения часового пояса: [AOSP Time overview](https://source.android.com/docs/core/connect/time).

## 5. Изоляция Claude

- Claude устанавливается только внутри защищённого профиля.
- Веб-версия открывается только защищённым браузером.
- Ссылки авторизации и внешние переходы должны обрабатываться внутри защищённой среды.
- Не допускать запуска незащищённой копии Claude в личном профиле.
- Запретить обход VPN через исключения для системных или сторонних приложений рабочего профиля.
- Изоляция не должна требовать изменения GPS, SIM, идентификаторов устройства или подмены системных данных.

**Claude Code в Termux:** отдельный сценарий второй очереди. Пока Termux находится в личном профиле, на него нельзя распространять гарантии защищённого рабочего профиля.

## 6. Совместимость устройства

Провести техническую проверку:

1. Возможность создания рабочего профиля на установленной прошивке.
2. Поддержка одновременных VPN-подключений в разных профилях.
3. Доступность системной настройки Always-on VPN внутри рабочего профиля.
4. Возможность включить Lockdown для рабочего профиля, не затронув личный.
5. Работа выбранного VPN-клиента в фоне и после перезагрузки.
6. Поведение при энергосбережении и ограничениях фоновой активности Motorola.
7. Доступные диагностические возможности ADB и Shizuku.

Если Shelter не обеспечивает необходимые политики, изучить штатный механизм Android Device Policy Manager и альтернативный контроллер рабочего профиля. Не использовать неофициальные обходы привилегий Android как обязательное условие.

## 7. План реализации

### Этап 1. Аудит устройства

- Определить текущие сетевые настройки.
- Проверить существующие рабочие профили.
- Выявить активные VPN-приложения и конфликты.
- Проверить поддержку требуемой политики.

**Результат:** подтверждённая совместимость или перечень технических ограничений.

### Этап 2. Создание среды

- Создать рабочий профиль.
- Развернуть совместимый VPN-клиент (для текущего исследования — DUORAY в рабочем профиле).
- Разместить Claude и браузер внутри профиля.
- Настроить единственный VPN-сервер.

**Результат:** защищённая среда без изменения личных данных пользователя.

### Этап 3. Применение защиты

- Активировать Always-on.
- Активировать Lockdown.
- Настроить IPv4/IPv6 и DNS.
- Исключить незащищённые маршруты.
- Проверить поведение при отказах.

**Результат:** подтверждённая схема Fail Closed.

### Этап 4. Автоматизация

- Восстановление VPN после перезапуска.
- Повторное соединение с тем же сервером.
- Контроль сохранения системных политик.
- Диагностика состояния туннеля.
- Безопасный сбор минимальных технических журналов.

Автоматизация не должна хранить ключи VPN или токены Claude в открытых логах.

### Этап 5. Тестирование

Проверить все штатные и аварийные сценарии, включая параметры окружения без принудительного изменения системного часового пояса. Результаты сохранить в протоколе с условиями испытаний, фактическими результатами и отметками PASS/FAIL.

## 8. Приёмочные испытания

Система принимается только при выполнении всех обязательных проверок.

| № | Проверка | Критерий PASS |
|---|---|---|
| T01 | IPv4 | Только выбранный VPN-выход |
| T02 | IPv6 | Через VPN или заблокирован |
| T03 | DNS | Нет прямых запросов в обход туннеля |
| T04 | VPN выключен | Интернет Claude недоступен |
| T05 | Сервер недоступен | Прямого подключения нет |
| T06 | Wi-Fi → LTE | Не обнаружено прямого трафика |
| T07 | Перезагрузка | Политика Lockdown сохраняется |
| T08 | Остановка VPN-клиента | Интернет профиля заблокирован |
| T09 | Браузер и авторизация | Нет выхода из защищённой среды |
| T10 | Личный профиль | Обычный интернет работает независимо |
| T11 | Энергосбережение | Защита не отключается |
| T12 | Обновление приложения | Защитная политика сохраняется |
| T13 | Часовой пояс | Текущее значение и механизм автоопределения зафиксированы; глобальные настройки не изменены без отдельного решения |
| T14 | Язык / локаль | Проверено разделение настроек рабочего приложения и личного профиля; изменения не влияют на личные приложения |
| T15 | Маршрутизация DUORAY | Автовыбор и запасные сервера отключены, отсутствие неразрешённого прямого egress подтверждено измерением |
| T16 | VPN профиля | Реальное VPN-соединение User 10 и блокировка при отказе испытаны независимо от личного DUORAY |

Тесты выполнять с использованием внешнего IP/DNS-контроля и, где технически возможно, независимого мониторинга сетевого трафика.

## 9. Аварийное восстановление

В случае невозможности включить профильный Lockdown:

- Не объявлять конфигурацию защищённой.
- Не использовать обычный Split Tunneling в качестве эквивалента Kill Switch.
- Предложить системный VPN с Lockdown для всего устройства как резервную архитектуру.
- Обозначить влияние на остальные приложения.

Перед созданием или удалением рабочего профиля обеспечить сохранность нужных данных. Удаление существующего рабочего профиля без отдельного согласия запрещено.

## 10. Критерии завершения

Проект считается технически завершённым, когда:

1. Все обязательные испытания пройдены.
2. Из рабочего профиля не выявлены прямые интернет-соединения.
3. Claude теряет интернет при любом протестированном отказе VPN.
4. Личный профиль продолжает штатно функционировать.
5. Подготовлена инструкция восстановления.
6. Зафиксированы версия ОС, VPN-клиента и итоговая конфигурация.
7. Документированы ограничения, которые невозможно устранить без root или изменения прошивки.

## 11. Что не входит в гарантии

Решение не гарантирует:

- Предотвращение блокировки аккаунта Anthropic.
- Обход проверки документов или личности.
- Сокрытие фактического региона проживания от всех возможных механизмов.
- Соответствие правилам Anthropic при использовании из неподдерживаемого региона.
- Защиту Termux, Claude Code и других приложений вне рабочего профиля без отдельной настройки.

**Итоговый ожидаемый результат:** технически проверенная, изолированная VPN-среда, в которой Claude не может случайно перейти с защищённого туннеля на обычный мобильный или Wi-Fi-интернет.
