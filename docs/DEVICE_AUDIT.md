# Этап 1 — аудит совместимости Lenovo Legion Y70

**Статус:** первый read-only запуск на целевом устройстве `PASS` (19 ноября 2026); проверка создания рабочего профиля и независимого VPN Lockdown — `NOT VERIFIED`. Тесты T01–T12 — `NOT RUN`.

## Цель

До создания рабочего профиля определить версию Android, присутствие других пользователей/профилей, доступность команд управления политиками и текущие *признаки* Always-on VPN/Lockdown по пользователям Android. Не менять настройки устройства и не удалять приложения.

## Запуск в Termux

Требуется работающий Shizuku + `rish` с UID 2000 (либо авторизованный `adb shell`). Скрипт самостоятельно выбирает `rish` из `PATH`, `$HOME/rish` или `adb`; предпочтителен Shizuku/rish. Для принудительного использования ADB: `CSN_SHELL=adb sh "$HOME/csn-device-audit.sh"`.

```sh
curl -fL https://raw.githubusercontent.com/lolokeksu09/claude-secure-network/main/scripts/device_audit.sh -o "$HOME/csn-device-audit.sh" && sh "$HOME/csn-device-audit.sh"
```

Перед запуском можно посмотреть содержимое: `cat "$HOME/csn-device-audit.sh"`.

Сохранение: `/storage/emulated/0/Download/claude-secure-network-audit-YYYYMMDD-HHMMSS.txt`. Если Download недоступен, отчёт сохраняется в `$HOME`. Скрипт не запрашивает root, не выполняет `settings put`, не запускает тестовые сетевые запросы и не перезапускает службы.

**Важно:** если Shizuku ещё не запущен, запустите его обычным штатным способом. Если `rish` не настроен, скрипт завершится сообщением, а не будет использовать обычный контекст Termux как доказательство Android shell.

## Как трактовать результаты

| Наблюдение | Вывод |
|---|---|
| Android release / SDK | Реальная версия прошивки на дату аудита |
| `managed_users_feature` | Признак функции; сам по себе не гарантирует возможность создать рабочий профиль |
| Несколько `user_ids` | Есть несколько пользователей/профилей; **тип профиля ещё не установлен** |
| `device_policy_owners` | Подсказка о действующих администраторах; ошибка чтения не означает их отсутствие |
| `always_on_vpn_app` | Значение настройки по пользователю; может быть `null`, не подтверждает работу туннеля |
| `always_on_vpn_lockdown` | Значение настройки по пользователю; только предварительный индикатор |
| Пакеты Claude/WireGuard/Shelter | Только наличие указанных приложений в выбранном пользователе |

**Порог завершения этапа:** по реальному отчёту и при необходимости ручной проверке системных настроек подтверждены тип рабочего профиля и фактическая возможность независимого Always-on + Lockdown. Если подтверждения нет — статус `BLOCKED / NOT VERIFIED`, а не PASS. Результат согласовать до любых изменений профилей.

## Безопасность и ограничения

- Отчёт сохранять **локально**, при необходимости передать в чат после просмотра. Публичный GitHub-репозиторий не предназначен для личных дампов устройства.
- Скрипт не читает серийные номера, IMEI, GPS, номера телефонов, содержимое VPN-конфигурации, токены, личные аккаунты, public IP или полные списки приложений.
- Не проверяются утечки IPv4/IPv6/DNS, WebRTC, реальная работоспособность Lockdown, отключение туннеля или сценарии перезагрузки: T01–T12 пока `NOT RUN`.
- Если установлен существующий рабочий профиль, его нельзя удалять/заменять без согласия и резервного копирования.

## Следующий шаг

1. Установить Shelter из доверенного источника; проверить создание нового рабочего профиля через интерфейс приложения. Создание профиля добавляет отдельное хранилище и набор приложений. **Удаление профиля удалит его данные**, поэтому не выполнять удаление или миграцию без резервной копии.
2. Повторить read-only аудит и проверить наличие нового пользователя, работу профиля и наличие настроек Always-on VPN в новом профиле.
3. Если профиль создаётся и позволяет независимую VPN-политику, выбрать WireGuard и проверить режим Lockdown; **до этой проверки не переносить Claude и не заявлять о защите**.
4. При невозможности профильного Lockdown рассмотреть системный VPN с Lockdown, не применяя его автоматически.
5. Только после подтверждения механизма выполнять сетевые тесты T01–T12 и фиксировать доказательства.

Официальное подтверждение того, что профильный администратор *может* назначать Always-on VPN, не доказывает доступность функции на конкретной прошивке: [Android Enterprise — Networking](https://developer.android.com/work/dpc/network-telephony.html).

Источники по механизму Android: [DevicePolicyManager](https://developer.android.com/reference/android/app/admin/DevicePolicyManager), [Android Enterprise — Networking](https://developer.android.com/work/dpc/network-telephony.html).
