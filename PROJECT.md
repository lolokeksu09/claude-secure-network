# PROJECT — Claude Secure Network

> Карточка проекта, адаптированная по Project Workflow Standard v1.0. Здесь только подтверждённые владельцем требования и известные ограничения; технически непроверенные решения помечены как предварительные.

| Поле | Решение / статус |
|---|---|
| Исходная цель | Для Claude — один фиксированный VPN-выход и отсутствие прямого трафика при сбоях. Остальные приложения по возможности работают через обычную сеть. |
| Пользователь | Владелец Android-смартфона Lenovo Legion Y70 с прошивкой Motorola. |
| Первая работающая версия (MVP) | Проверенный на целевом устройстве сценарий: защищённое приложение выходит в сеть через один VPN-туннель; при отказе туннеля интернет этого приложения недоступен. |
| Критерий готовности MVP | На реальном телефоне подтверждены положительный и отрицательный сценарии: активный туннель → только VPN-выход, выключенный туннель → отсутствие прямого сетевого доступа. |
| Поддерживаемая платформа | Lenovo Legion Y70 с прошивкой Motorola: read-only аудит 2026-11-19 подтвердил Android 17 / API 37; поддержка Work Profile + независимого Lockdown ещё не проверена. |
| Привилегии | Основной вариант без root; Shizuku/Termux могут применяться для диагностики, но не считаются заменой Android VPN Lockdown. |
| Предпочтительная архитектура | Собственный CSN Guardian как Profile Owner нового рабочего профиля + совместимый VpnService-клиент (DUORAY/VLESS или WireGuard) + Android Always-on/Lockdown. На телефоне не активировано. |
| Объём первого этапа | Аудит совместимости, затем минимальный сквозной сценарий и объективные сетевые проверки. |
| Вне объёма первого этапа | Автоматическая замена Shelter, обход блокировок аккаунта, подмена региона устройства или документов, миграция Termux/Claude Code. |
| Формат результата | Git-репозиторий с ТЗ, Android-кодом CSN Guardian, CI и планом испытаний; реальное внедрение на Lenovo — отдельный этап. |
| Разрешённые действия | Подготовка структуры и документации репозитория по запросу владельца. Действия с телефоном и секретами требуют отдельной задачи. |

## Открытые решения

1. **Поддержка отдельного Always-on/Lockdown.** Рабочий профиль Shelter создан и подтверждён как `ManagedProfileOwner` (`User 10`); возможность независимого Lockdown на прошивке ещё не проверена. При отсутствии поддержки альтернативой служит VPN с Lockdown для всего устройства, с отдельным согласованием влияния на другие приложения.
2. **VPN-сервер.** Конкретная страна, IP и способ размещения не определены. Эти параметры не нужно выдумывать и нельзя коммитить приватные конфигурации.
3. **Использование Claude Code.** Изоляция Termux вне рабочего профиля в начальный объём не входит.
4. **Юридические/сервисные ограничения.** Действующая политика Anthropic в неподдерживаемых регионах не устраняется сетевой конфигурацией.

## Расширение проекта: CSN Guardian

Решение пользователя (20 ноября 2026): разработать собственное специализированное приложение, управляющее рабочим профилем строже Shelter. Основа — собственный Android DPC без копирования чужого кода и без доступа в интернет. Стартовая реализация в ветке `feat/csn-guardian-dpc` и [документе архитектуры](docs/GUARDIAN_ARCHITECTURE.md).

- Целевая роль: `Profile Owner` **нового** профиля, не второго владельца существующего Shelter.
- Первые функции: обнаружение VPN-служб, безопасное назначение Always-on/Lockdown, чтение политики и аварийный откат.
- Не реализованы: перенос Shelter, контроль фактического сетевого выхода, firewall поверх штатного Android, проверка утечек, релиз и аппаратная приёмка.
- Сборка и unit-тесты `0.1.0-alpha` пройдены в GitHub Actions: [run 44706330604](https://github.com/lolokeksu09/claude-secure-network/actions/runs/44706330604). Это **не** тест на целевом телефоне.
- Не допускать удаления Shelter User 10 и приватных данных без отдельного подтверждения и резервной копии.
